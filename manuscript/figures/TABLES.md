# Tables

Publication-form tables for *Divergence Ranks What Benchmarks Bound*. **Every table names its n, its
estimator, its interval and its protocol inside the table**, per the project's hard rule 5. Values are
generated by [`extract.py`](extract.py) into [`data/`](data/); each table names the file it is drawn
from, so a reader can check any cell against the artifact.

**Provenance classes.** `measured` (run on this host, artifact committed) · `recomputed` (derived from
committed per-item records at zero GPU cost) · `cited` (external) · `modelled` (GPU telemetry + RAPL +
a fixed platform allowance; no wall-socket sensor) · `historical` (pre-2026-08-29,
*irreproducible-on-current-images*, PN-57).

**Protocols are never mixed inside a table.** Where two protocols measure the same quantity, they are
in different tables (T18) or in explicitly separated blocks with the protocol in the row.

## T4 · Code-to-prose amplification by quantile

*Source: `data/fig02-tail-amplification.csv` (panel a). PN-35, corrected by **PN-64**; scoped by PN-62.*

| statistic | UD-Q6_K | UD-Q5_K_XL | UD-Q4_K_XL | interval basis |
|---|---|---|---|---|
| median | *0.0050×* | *0.0055×* | *0.0048×* | print precision, ±7.2 / ±5.0 / ±3.0 % — **not rankable** |
| p90 | 0.449× | 0.541× | 0.613× | print precision, ≤0.03 % |
| **p95** | **1.527×** | **1.888×** | **2.184×** | print precision, ≤0.02 % |
| p99 | 4.988× | 6.709× | 8.090× | print precision, ≤0.01 % |
| p99.9 | 6.352× | 8.528× | 8.448× | print precision |
| *mean (this is PN-14's headline)* | *1.755×* | *2.304×* | *2.623×* | tool-reported SE, ±7.8 / ±10.8 / ±8.0 % |
| maximum (single token) | 0.629× | 0.813× | 0.730× | print precision |

Crossover: **between p90 and p95 for all three arms** — p90 is below unity on all three, p95 above it
on all three. Above the crossover the amplification is monotone in aggressiveness at every quantile.
The single worst token is *less* perturbed on code than on prose, so the effect is a p95–p99.9 band,
not an unbounded tail.

> **The median row cannot rank the arms (PN-64).** `llama-perplexity` prints six decimals, so the code
> medians (0.000007 / 0.000010 / 0.000017) carry one to two significant figures; half-ULP propagation
> gives the intervals above and UD-Q6_K's overlaps both others. State the median contrast as
> **"about 200×"** (measured prose ÷ code: 199 / 181 / 206) and do not tabulate it per arm in the body.
> **PN-35's published "100–200×" is withdrawn** — the 100 was the reciprocal of a rounded table cell.
>
> **Ratio at p99 ÷ ratio at the mean = 2.84 / 2.91 / 3.08**, a near-constant, so the p99 row is the
> mean row scaled by ≈2.9 and not an independent effect (PN-62).

(`torch.OutOfMemoryError: Tried to allocate 1.19 GiB` inside `EagleDraftWorker` init, at every context
tried — 131,072 / 65,536 / 32,768 / 16,384); vLLM nightly with a BF16 DFlash2 drafter (3.6 GB) at an
**identically sized** 1.19 GiB allocation, at every GPU-utilisation setting 0.78–0.97 and every draft
depth; llama.cpp with a 4-bit GGUF drafter (1.1 GB) **succeeds**. MTP sidesteps it entirely because
its predictor is a head inside the checkpoint rather than a second model, and therefore works on both
backends.

> **This table compares different quantizations on different engines** — NVFP4 (W4A4, fp8 KV) against
> UD-Q4_K_XL (q4_0 KV): backend, quantization, KV dtype and speculative method all vary at once, so no
> single-variable conclusion follows from any pairwise comparison. **Depth-0 decode**; at a genuinely
> full window the same class of configuration is 2–3× slower (T12) and these rows must never be quoted
> as long-context throughput. The vLLM ceiling is a **boot-verified KV-pool figure**, not a
> behaviourally verified one — the battery was aborted before the deep-prefill arm ran. SGLang must be
> described as *attempted and could not be brought up*, never as benchmarked and lost. The identical
> 1.19 GiB figure across two unrelated stacks is **unexplained** and is reported as an observation.
